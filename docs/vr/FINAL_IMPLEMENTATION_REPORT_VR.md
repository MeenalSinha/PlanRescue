## A. Executive Summary

PlanRescue Spatial transforms traditional 2D calendar and schedule-recovery workflows into an interactive, immersive spatial productivity experience designed for Meta Quest headsets (Horizon OS) and modern WebXR runtimes. 

When schedule disruptions occur—such as an urgent morning meeting running 45 minutes late—standard flat productivity tools merely display overlapping calendar alerts, leaving users with the cognitive fatigue of manually renegotiating downstream commitments, travel windows, and task deadlines. PlanRescue Spatial transports the user into an interactive 3D productivity studio where daily schedules, tasks, disruptions, and recovery alternatives exist as tangible spatial objects.

Using natural optical hand tracking (or 6DoF Touch controllers), users inspect their day, define disruptions through physical duration steppers, visualize cascading downstream conflicts in real time, explore multi-candidate recovery proposals generated by a deterministic scheduling engine, compare Before-vs-After schedules on a dual-track spatial workspace, verify independent constraint validations, and safely execute approved schedule adjustments through an atomic, server-enforced two-step confirmation workflow with stale-plan protection.

All eight product phases (Phases 0 through 8) have been fully implemented, integrated with the existing backend architecture, verified against zero-data-fabrication and zero-hardcoding principles, and validated with 16 automated test suites containing 61 passing tests in `apps/vr` (408 passing automated tests across the whole repository including a dedicated end-to-end SQLite and Deterministic Engine integration suite).

## C. Phase-by-Phase Implementation Architecture & Deliverables

### Phase 2: Spatial Environment & Visual Design System
- **Ergonomic 3-Zone Studio Layout:** Structured the virtual productivity studio into three spatial arcs within Quest visual comfort envelopes (1.2m to 2.2m distance, -15° to +20° vertical gaze, ±45° horizontal azimuth):
  - *Left Wing (-35° azimuth, 1.4m distance):* Disruption & Scenario Management Panel.
  - *Center Stage (0° azimuth, 1.4m distance):* Spatial Timeline, Task Panel, and Dual-Track Comparison Workspace.
  - *Right Wing (+35° azimuth, 1.4m distance):* PlanRescue AI Assistant, Independent Validation Explorer, and Action History / Audit Trail.
- **Design Token System (`apps/vr/src/ui/tokens.ts`):** Centralized design palette:
  - Surfaces: Dark glassmorphic panels (`0x0f172a`), borders (`0x334155`), hover glow (`0x00e5ff`).
  - Semantics: Primary PlanRescue Cyan (`0x00e5ff`), AI Purple (`0x8b5cf6`), Indigo (`0x6366f1`).
  - Priority Authority: Critical (`0xef4444`), High (`0xf97316`), Medium (`0x3b82f6`), Low (`0x10b981`).
  - Physical Dimensions: Standard panel widths/heights, event cards, buttons, and elevation depths.
- **Spatial UI Components (`apps/vr/src/ui/components.ts`):** Implemented `SpatialUIElement`, `SpatialPanel`, `SpatialCard`, `SpatialButton`, `SpatialLoadingIndicator`, and `SpatialStudioEnvironment` (ambient lighting, directional key light, and reference ground grid).

### Phase 3: Hand Tracking & Natural Interaction System
- **Input Source Orchestration (`apps/vr/src/interaction/handInteractionManager.ts`):** 
  - Polls `XRInputSourceArray` joints and target rays each frame.
  - Computes direct raycaster intersections with interactive UI meshes (`SpatialButton`, `SpatialCard`).
  - Handles pinch-to-select and pinch-to-grab gesture transitions with ray visual feedback.
  - Projects grabbed objects onto virtual constraint planes (e.g. timeline axis) for natural dragging.
- **Desktop Emulation Fallback (`apps/vr/src/interaction/desktopInteraction.ts`):** 
  - Translates mouse movement and click/drag events on the WebGL canvas into raycast intersections, enabling complete development on standard desktop browsers.
- **Spatial Onboarding Tutorial (`apps/vr/src/interaction/onboarding.ts`):** 
  - Step-by-step interactive 3D HUD teaching gaze targeting, ray pointing, pinch selection, and grab-drag movements.
  - Persists completed tutorial state to `localStorage` to avoid intrusive re-prompting.

### Phase 4: Spatial Calendar & Interactive Timeline
- **Proportional Spatial Timeline (`apps/vr/src/calendar/spatialTimeline.ts`):** 
  - Represents daily schedule horizontally (1.4m width, 0.22m height) across the active planning horizon (e.g. 08:00 to 20:00).
  - Positions `SpatialEventBlock` meshes proportionally along the X-axis based on exact event start times and durations.
  - Displays priority accent stripes along card edges and fixed-event lock badges (`🔒 Fixed`) on immovable commitments.
  - Interactive draft manipulation: dragging movable events snaps to 15-minute intervals along the timeline axis with dynamic timestamp tooltips.
- **Spatial Task Panel (`apps/vr/src/calendar/taskPanel.ts`):** 
  - Renders pending tasks with priority badges, estimated durations, and deadline feasibility status indicators (`feasible` / `at_risk`).

### Phase 5: Disruption Detection & Interactive Scenario Management
- **Bounded Disruption Definition (`apps/vr/src/disruption/disruptionPanel.ts`):** 
  - Allows user to select an active calendar event and declare overrun delays strictly bounded between 1 and 240 minutes.
  - Provides instant presets (+15m, +30m, +45m, +60m) alongside fine-grained ±5m steppers.
  - Computes and displays projected overrun completion times in real time.
- **Spatial Conflict Visualizer (`apps/vr/src/disruption/conflictVisualizer.ts`):** 
  - Immediately calculates and highlights downstream cascading collisions and threatened task deadlines resulting from the projected overrun.
  - Distinguishes high-severity direct collisions from downstream warnings.

### Phase 6: Recovery Engine Integration & Grounded Explainable AI
- **Multi-Strategy Recovery Orchestration (`apps/vr/src/recovery/recoveryManager.ts`):** 
  - Triggers `proposeRecovery()` via `PlanRescueApiClient` with `saveCandidates: true`.
  - Captures server-generated candidate plans across all three deterministic strategies:
    1. `minimal_disruption`: Minimizes number of moved events and total shift minutes.
    2. `buffered_transitions`: Provides protective breathing buffers between rescheduled events.
    3. `priority_first`: Defends high-priority commitments by displacing lower-priority items.
  - Captures SQLite `persistentId` and `savedStatus` directly from backend route handlers.
  - Computes penalty decompositions (delay penalty, event movement penalty, task overflow penalty).
- **PlanRescue AI Assistant Panel (`apps/vr/src/assistant/spatialAssistant.ts`):** 
  - Generates grounded, factual natural explanations explaining *why* the recommended plan was selected, which protected events were preserved, and what trade-offs were made.
  - Zero hallucination: explanation strings are constructed strictly from validated plan attributes and candidate scores.
  - Infeasible scenario handling: clearly explains constraint violations when disruptions cannot be resolved.

### Phase 7: Spatial Recovery Comparison & Explainable AI
- **Dual-Track Comparative Workspace (`apps/vr/src/comparison/comparisonWorkspace.ts`):** 
  - Positions Before (Current Schedule) and After (Proposed Recovery) timelines on parallel vertical tracks separated by 0.16m.
  - Dynamically highlights differences: shifted events, shortened durations, displaced tasks, and preserved protected events.
  - Allows one-touch switching between candidate strategy proposals.
- **Independent Validation Explorer (`apps/vr/src/comparison/validationExplorer.ts`):** 
  - Displays independent validator checks:
    - Time-window boundary constraints (`within_working_hours`).
    - Fixed-event immutability checks (`protected_events_unmoved`).
    - Break minimum requirements (`lunch_break_preserved`).
    - Task deadline feasibility (`task_deadlines_feasible`).
  - Differentiates hard fatal violations (`status: invalid`) from operational recommendations (`status: warning`).

### Phase 8: Approval, Execution & Spatial Audit Trail
- **Two-Step Approval & Atomic Execution (`apps/vr/src/execution/approvalWorkflow.ts`):** 
  - *Step 1 (Explicit Approval):* User triggers "Approve Plan Proposal". Submits `POST /api/recovery/plans/[planId]/approve`. State transitions to `approved`. The schedule remains unmutated.
  - *Step 2 (Execution Confirmation):* A separate confirmation button ("Confirm & Execute Schedule Changes") activates. Clicking triggers `POST /api/recovery/plans/[planId]/apply`. The backend atomically updates calendar events within a single SQLite transaction.
  - *Stale-Plan Rejection:* If the schedule changed concurrently between proposal and execution, the backend rejects with a stale snapshot error. The workflow catches this, displays a stale warning alert, and prompts the user to recalculate.
- **Spatial Action History & Audit Trail (`apps/vr/src/history/spatialActionHistory.ts`):** 
  - Displays the persistent, chronological audit trail fetched from `GET /api/actions/history`.
  - Renders timestamped cards detailing planning requests, approvals, rejections, and atomic executions with actor metadata.

### Phase 9: User Accounts, Identity & Personalization
- **Auth & Identity Service (`apps/web/src/lib/auth/service.ts`, `apps/web/src/lib/auth/db.ts`):**
  - Dedicated, isolated SQLite auth store (`data/planrescue-auth.sqlite`) with tables `users`, `sessions`, `user_preferences`, `user_plan_ownership`.
  - Cryptographically secure scrypt password hashing and 256-bit session token generation.
  - Strict plan ownership isolation: cross-user plan inspection and execution attempts are rejected with 403 Forbidden.
  - Next.js API route handlers: `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/session`, `/api/user/preferences`.
- **3D Spatial Account & Comfort Panel (`apps/vr/src/account/spatialAccountPanel.ts`):**
  - Mounted on the lower tier of the Right Wing (1.15m x, 0.35m y, -1.0m z).
  - Displays authenticated user profile, timezone, working hours, and spatial comfort settings.
  - Interactive strategy cycle button allowing users to toggle preferred strategy defaults (`minimal_disruption`, `buffered_transitions`, `priority_first`) directly in VR.

### Phase 10: External Calendar Integrations
- **Provider Adapters (`apps/web/src/lib/calendar/providers/`):**
  - Google Calendar API v3 adapter (`google.ts`) normalizing external events to domain events and implementing ETag / 412 Precondition Failed concurrency checks.
  - Microsoft Graph Outlook Calendar adapter (`outlook.ts`) handling timezones, importance weighting, and delta link tokens.
  - Local SQLite calendar provider retaining zero-dependency local offline capability.
- **Bi-directional Sync & Outbox Saga (`apps/web/src/lib/calendar/syncManager.ts`):**
  - Idempotent calendar synchronization mapping provider event IDs to local event IDs in `external_calendar_mappings`.
  - External sync outbox (`external_sync_outbox`) queuing schedule shifts upon approved plan execution.
  - Asynchronous reconciliation pushing modified timestamps to external providers without blocking primary ACID transactions.
- **VR Integration:**
  - API routes: `/api/calendar/providers`, `/api/calendar/connect`, `/api/calendar/sync`, `/api/calendar/disconnect`.
  - Spatial account panel displays connected provider indicators and interactive "Sync Calendars" button.

### Phase 11: Advanced AI & Productivity Intelligence
- **Productivity Intelligence Engine (`apps/web/src/lib/intelligence/productivityEngine.ts`):**
  - Calculates deterministic Schedule Health Score (0–100) based on overload percentage, back-to-back transitions, focus time fragmentation (< 30 min gaps), and context switches.
  - Generates grounded, explainable recommendations (e.g. "Back-to-Back Meeting Fatigue: insert 10m buffer", "Consolidate fragmented gaps into a deep work block").
  - API route: `GET /api/productivity/insights`.
- **Expanded Disruption Scenarios (`apps/web/src/lib/intelligence/disruptions.ts`):**
  - `event_overrun`: standard meeting overruns.
  - `time_window_unavailable`: blocks unavailable windows (personal emergency, transit) using synthesized immovable events.
  - `urgent_task_added`: injects emergency high-priority tasks into task capacity assessment.
- **3D Spatial Productivity Panel (`apps/vr/src/intelligence/spatialProductivityPanel.ts`):**
  - Mounted on the lower tier of the Left Wing (-1.15m x, 0.35m y, -1.0m z).
  - Renders health score ring (green >= 80, amber 60–79, red < 60), focus time meter, and grounded recommendation cards.

### Phase 12: Security, Privacy & Reliability Hardening
- **Threat Modeling & Prompt Injection Sanitizer (`apps/web/src/lib/security/sanitizer.ts`):**
  - Normalizes Unicode to NFC, strips ASCII control characters and null bytes.
  - Neutralizes prompt injection attempts (`ignore previous instructions`, `bypass approval`, `system:`) and strips unsafe script tags.
- **AES-256-GCM Token Encryption (`apps/web/src/lib/security/crypto.ts`):**
  - Encrypts sensitive calendar OAuth tokens using AES-256-GCM with 96-bit IV and 128-bit authentication tags.
- **Sliding-Window Rate Limiter (`apps/web/src/lib/security/rateLimiter.ts`):**
  - Protects sensitive authentication and recovery endpoints against brute-force and scraping.
- **GDPR Privacy Rights & Health Check:**
  - `GET /api/user/export`: Portable JSON export of user profile, preferences, calendar accounts, and plan ownership records.
  - `POST /api/user/delete`: Cascading deletion of user records and anonymization of audit logs.
  - `GET /api/healthz`: High-availability readiness and liveness probe verifying database connectivity and server uptime.

## E. Architecture Decision Records (ADRs) Summary

All major architectural choices are formally documented in [`docs/vr/ARCHITECTURE_DECISIONS.md`](file:///c:/Users/Meenal%20Sinha/Downloads/PlanRescue/docs/vr/ARCHITECTURE_DECISIONS.md):

- **ADR-001: Independent Package Isolation for `apps/vr`**  
  *Decision:* Retain `apps/vr` as an isolated package with dedicated `package.json`, `tsconfig.json`, and Vite config, excluded from backend NodeNext compilation.
- **ADR-002: Server-Side API Boundary for VR Integration**  
  *Decision:* VR client communicates exclusively through Next.js server route handlers, protecting SQLite and MCP credentials from client-side exposure.
- **ADR-003: Manifest-First Meta IWSDK Architecture with `iwsdk.config.json`**  
  *Decision:* Use official Meta IWSDK v1.1.0 manifest-first configuration and `iwsdkDev()` Vite plugin.
- **ADR-004: Centralized Strict Configuration Schema with Runtime Injection**  
  *Decision:* Enforce Zod validation on configuration loaded via priority cascade (window -> json -> env).
- **ADR-005: Strict Capability Detection vs. Emulation Truthfulness**  
  *Decision:* Distinguish configured, supported, available, and active XR states. Never misreport desktop emulation as hardware certification.
- **ADR-006: Structured Diagnostics and Sensitive Data Redaction**  
  *Decision:* Redact auth headers, tokens, and PII from client-side logging and diagnostic dumps.
- **ADR-007: Three-Zone Spatial Studio Layout and Design Token Architecture**  
  *Decision:* Position Left, Center, and Right functional wings within Quest visual comfort envelopes (1.2m–2.2m distance, ±45° horizontal azimuth).
- **ADR-008: Direct Pointer Ray & Proportional Drag-Plane Hand Interaction**  
  *Decision:* Implement raycast pointer interactions with pinch grab and planar constraint projection, with desktop mouse fallback.
- **ADR-009: Proportional Spatial Timeline with 15-Minute Snapping and Fixed-Event Locks**  
  *Decision:* Map schedule times to a 1.4m horizontal bar with lock badges on fixed events and 15m draft snapping.
- **ADR-010: Boundary-Constrained Disruption Definition & Conflict Visualization**  
  *Decision:* Limit overrun delays between 1–240 min with presets and immediate downstream conflict rendering.
- **ADR-011: Server-Grounded Multi-Strategy Recovery Engine Integration**  
  *Decision:* Generate proposals across all three strategies with `saveCandidates: true`, capturing persistent SQLite IDs.
- **ADR-012: Dual-Track Comparative Workspace & Validation Explorer**  
  *Decision:* Parallel Before/After tracks with diff highlighting and hard/warning independent validation checklists.
- **ADR-013: Server-Enforced Two-Step Approval/Execution Separation & Audit Trail**  
  *Decision:* Decouple approval from atomic execution, detect stale plans, and surface the persistent SQLite action history.

## H. Known Limitations, Hardware Specifics & Environment Notes

1. **Hardware Verification Context:**
   - Physical Meta Quest hardware verification requires deploying the built bundle to an HTTPS-enabled origin accessible by the Meta Quest Browser.
   - Desktop browser execution relies on `DesktopInteractionFallback` (mouse raycasting) or the Meta WebXR Emulator extension.
   - The capability detection module honestly differentiates between desktop emulation and physical headset sessions.
2. **Local Sandbox Network Isolation:**
   - In sandboxed command execution environments on Windows, TCP loopback socket connections between separate processes (`127.0.0.1:PORT`) are restricted by OS sandbox policy. 
   - All unit, component, and mocking integration tests execute cleanly in-process without sandbox violations.
3. **Calendar Integration Scope:**
   - PlanRescue Spatial acts directly on its local, transaction-safe SQLite database (`data/planrescue.sqlite`). Enterprise synchronization with external calendar APIs (Google Calendar, Outlook 365) is intentionally architected as a server-side connector extension.
